	Iterators	


Before writing any code, you must understand two terms that are often confused:


IterableIteratorSomething you CAN loop overSomething that PRODUCES values one at a timeHas an  iter () method that returns an iteratorHas both   iter  () and   next  () methodsExamples: list, tuple, str, dict, set, rangeRemembers where it is (has internal state)Does NOT have  next () itselfOnce exhausted, it's done - cannot reset
Every iterator is an iterable, but not every iterable is an iterator.

Checking what's iterable vs what's an iterator:







The iterator protocol is a formal contract: any object that implements both   iter	and  next	 correctly is an iterator. Python relies on this contract for loops, comprehensions, and unpacking.


MethodSignatureWhat It Must DoCalled By  iter	def  iter (self):Return the iterator object itself (return self)iter(obj) and for loops  next	def  next (self):Return the next value; raise StopIteration when exhaustednext(obj) and for loops

Why	iter	returns self?	
An iterator must itself be iterable so that it can be used directly in a for loop or passed to any function that expects an iterable. Returning self satisfies that requirement.

Minimal iterator protocol example:
class CountUp:def  init (self, start, stop):self.current = startself.stop	= stopdef  iter (self):return self	# returns itself - satisfies the protocoldef  next (self):if self.current > self.stop:raise StopIteration	# signal that we are donevalue = self.currentself.current += 1return valuecounter = CountUp(1, 5)for n in counter:print(n, end=' ')#12345

The difference is deeper than just yield vs return. They have fundamentally different execution models.


AspectRegular FunctionGenerator FunctionKeyword usedreturnyieldReturnsA single value, then endsA generator object (lazy iterator)ExecutionRuns completely, top to bottomPauses at each yield, resumes on next()StateAll local vars lost after returnAll local vars preserved between yieldsMemoryBuilds full result in memoryOne value at a time - very memory efficientReusable?Yes - call it again any timeNo - once exhausted, must recreateStopIterationNot applicableRaised automatically when function endsUse forSimple calculations, small resultsLarge sequences, streams, pipelines

	hash	- Why It Pairs with	eq	
Python's rule: objects that compare equal must have the same hash. That is why defining   eq	 automatically sets  hash	to None (making the object unhashable) unless you also define   hash	 yourself.
Rule: if a == b then hash(a) == hash(b)
